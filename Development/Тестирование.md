# Тестирование кода
## Типичная пирамида тестирования
- **70%** — unit
- **20%** — integration / API
- **10%** — e2e

## Unit-тестирование (модульное)
>[!info] **Unit-тестирование** — это проверка **минимальных логических единиц кода** (functions / methods / classes) **в изоляции от внешнего мира**.

**Unit-тесты проверяют:**
- корректность **бизнес-логики**
- граничные условия
- обработку ошибок
- возврат значений
- выбрасывание исключений
- поведение функции при разных входных данных
    
**Unit-тест НЕ проверяет:**
- реальную БД
- реальные HTTP-запросы
- файловую систему
- работу сторонних сервисов
- корректность роутинга
Все внешние зависимости **мокаются**.

**Основные требования к unit-тесту**
Хороший unit-тест:
1. **Быстрый** (миллисекунды)
2. **Детерминированный**
3. **Изолированный**
4. **Проверяет одно поведение**
5. **Читается как спецификация**

#### Примеры
Код, который тестируем
```python
# services/discounts.py

def calculate_discount(price: float, is_vip: bool) -> float:
    if price <= 0:
        raise ValueError("Price must be positive")

    discount = 0.1 if is_vip else 0.05
    return round(price * (1 - discount), 2)
```

Unit-тесты
```python
# tests/unit/test_discounts.py

import pytest
from services.discounts import calculate_discount


def test_vip_discount():
    result = calculate_discount(100, is_vip=True)
    assert result == 90.0


def test_regular_discount():
    result = calculate_discount(100, is_vip=False)
    assert result == 95.0


def test_invalid_price_raises_error():
    with pytest.raises(ValueError):
        calculate_discount(0, is_vip=True)
```

Что здесь важно:
- нет БД
- нет фреймворка
- чистая логика
- проверка ошибок

###### Пример с моками
Код, который тестируем
```python
# services/payments.py

def charge_user(gateway, user_id: int, amount: float) -> bool:
    if amount <= 0:
        raise ValueError("Amount must be positive")

    return gateway.charge(user_id=user_id, amount=amount)
```

Unit-тест с mock
```python
# tests/unit/test_payments.py

from unittest.mock import Mock
import pytest
from services.payments import charge_user


def test_charge_user_success():
    gateway = Mock()
    gateway.charge.return_value = True

    result = charge_user(gateway, user_id=1, amount=100)

    assert result is True
    gateway.charge.assert_called_once_with(user_id=1, amount=100)


def test_charge_user_invalid_amount():
    gateway = Mock()

    with pytest.raises(ValueError):
        charge_user(gateway, user_id=1, amount=-10)
```

Здесь:
- `gateway` — внешняя система
- мы **не дергаем реальный платежный сервис**
- проверяем только свою логику

**Типичные ошибки:**
1. Unit-тесты, которые ходят в БД
2. Unit-тесты, которые стартуют Django/FastAPI
3. Один тест проверяет несколько сценариев
4. Тесты, зависящие от порядка выполнения
5. Избыточные mocks без необходимости

## Интеграционное тестирование
>[!info] **Интеграционное тестирование** проверяет **взаимодействие нескольких компонентов системы между собой** с использованием **реальных зависимостей**. Мы тестируем не отдельную функцию, а **цепочку компонентов**, но **не всю систему целиком**.

Интеграционные тесты проверяют:
- корректность работы **ORM + БД**
- взаимодействие **service → repository**
- сериализацию / десериализацию данных
- работу транзакций
- реальные настройки приложения
- работу middleware
- интеграцию с кэшем, очередями (часто в тестовом режиме)

**Обычно используются реальные:**
- БД (PostgreSQL / SQLite)
- ORM
- конфигурация приложения

**Обычно НЕ используются:**
- UI
- браузер
- реальные сторонние API (они мокаются или подменяются)

#### Инструменты
###### Общие
- `pytest`
- `pytest-django`
- `pytest-asyncio`
- `testcontainers` (для PostgreSQL, Redis)
    
###### FastAPI
- `fastapi.testclient.TestClient`
- `httpx.AsyncClient`
    
###### Django
- `django.test.TestCase`
- `pytest-django`

#### Пример интеграционного теста (FastAPI)
Код, который тестируем
```python
# app/main.py

from fastapi import FastAPI, Depends
from sqlalchemy.orm import Session
from app.db import get_db
from app.models import User

app = FastAPI()


@app.post("/users")
def create_user(name: str, db: Session = Depends(get_db)):
    user = User(name=name)
    db.add(user)
    db.commit()
    db.refresh(user)
    return {"id": user.id, "name": user.name}
```

Интеграционный тест
```python
# tests/integration/test_users.py

from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app)


def test_create_user(db_session):
    response = client.post("/users", params={"name": "Alice"})

    assert response.status_code == 200
    assert response.json()["name"] == "Alice"
```

#### Пример интеграционного теста (Django)
Код, который тестируем
```python
# users/models.py

from django.db import models

class User(models.Model):
    name = models.CharField(max_length=100)
```
```python
# users/views.py

from django.http import JsonResponse
from .models import User

def create_user(request):
    user = User.objects.create(name=request.POST["name"])
    return JsonResponse({"id": user.id, "name": user.name})
```

Интеграционный тест
```python
# users/tests/test_integration.py

from django.test import TestCase
from django.urls import reverse
from .models import User


class CreateUserIntegrationTest(TestCase):
    def test_create_user(self):
        response = self.client.post(
            reverse("create_user"),
            {"name": "Bob"}
        )

        self.assertEqual(response.status_code, 200)
        self.assertEqual(User.objects.count(), 1)
        self.assertEqual(User.objects.first().name, "Bob")
```

#### Типичные ошибки
1. Слишком много логики в unit — интеграция не тестируется
2. Интеграционные тесты с внешними API без изоляции
3. Долгие тесты без очистки БД
4. Смешивание E2E и integration в одном наборе
5. Запуск всего приложения без необходимости

## Smoke-тесты
Минимальный набор проверок “приложение вообще работает”.

- Сервер запускается
- Основные эндпоинты доступны
- БД подключена

Где применяется:
- CI/CD
- После деплоя
